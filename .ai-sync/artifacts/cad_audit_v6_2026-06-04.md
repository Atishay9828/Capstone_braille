## 1. ⚠️ FALSE ALARMS — DO NOT "FIX" THESE
Two agents raised "critical bugs" that are **wrong**. Verified against source:

1. **Magnet polarity is CORRECT (not a repulsion bug).**
   - Chain always docks a `+X` face to a `−X` face: `pod+X → cell−X`, `cell+X → cell−X`, …
   - `−X` faces are **N/S/N**, `+X` faces are **S/N/S** → opposite poles meet → **ATTRACT**.
   - Verified: `outer_box.scad:14,130`, `esp32_pod_shell.scad:49`, `esp32_pod_params.scad:63`.
   - The agent error assumed `+X` meets `+X`. It never does in a daisy-chain.
   - **NOTE:** OpenSCAD models magnets as identical cylindrical pockets anyway — polarity is an
     assembly-time decision documented in comments, not geometry. Nothing to change.

2. **`linkage.scad` reference table is only a STALE COMMENT, not broken geometry.**
   - The comment table near the bottom lists `arm_span`/`asm_ang` computed with the OLD
     `inner_radius=8`. The **live code computes these from functions at render time** with the
     current `inner_radius=12.0` (`linkage.scad:55`). Geometry is correct. (Optional: refresh
     the comment for tidiness; not functional.)

## 4. BRAILLE PITCH — NUMBERS (kept as rationale for the eventual patent doc)
- **Standard braille:** dot Ø 1.44–1.6mm, dot height 0.46–0.50mm, within-cell pitch ~2.5mm,
  cell-to-cell ~6.1–6.5mm, line-to-line ~10mm.
- **Braillix:** horizontal `col_spacing=4.8mm` (~1.9× wide), vertical `row_spacing=2.6mm` (≈ std),
  dot = 2mm ball, nub 2.2mm, hole 2.5mm, rise 0.8mm.
- **Why 4.8:** two 2.5mm holes at 2.5mm pitch touch edges and merge; the 2mm ball/2.2mm nub is
  too fat to pack tighter. A standard build would need ball→1.5, nub→1.6, hole→1.9, pitch→2.5,
  and the 4.5mm return-spring pockets would overlap (need micro-springs OR gravity+shared return).
- **DEEPEST TRUTH (architecture):** each cell is a **68mm cube → characters sit 68mm apart** vs
  6.1mm standard. A 28BYJ-48 is **28mm Ø**, so one-motor-per-character at reading pitch is
  physically impossible. → Braillix is honestly a **modular braille teaching / single-character
  display**, not a compact multi-char reader. Frame it that way in the patent.

## 6. QOL / NEW FEATURES BEING ADDED THIS PASS
1. ~~**Anti-reversal dock keying** (post/slot)~~ — **REVERTED 2026-06-04 per Mridul** (external
   bump looked bad on the clean brick). Analysis for the record: magnets DO catch a wrong-*face*
   dock (repel), but do NOT catch an **upside-down** dock (magnet pattern is symmetric about the
   X flip → still attracts). Upside-down reverses the 4 pogo pins' Y-order → upstream 5V lands on
   the flipped cell's SCL pin → **not a supply short, but 5V on the I²C lines can damage the
   non-5V-tolerant ESP32 GPIOs.** Mitigation deferred to the CONNECTOR/electrical level (cleaner
   than a bump): options = (a) use a polarized/keyed 4-pin pogo connector, (b) place the pogo
   window enough off-vertical-center that a flipped cell's pins simply don't meet (open circuit =
   safe), or (c) series protection on the bus. TODO when the real pogo part is chosen.
2. **Pod-vs-cell tactile ID** — raised braille ⠿ (all-6) on pod lid (also clears the long-pending
   "⠿ on pod" task).
3. **Nav-cap braille labels** P/S/N under the ◁○▷ domes.
4. **Power-jack guard ring** around the barrel jack.
5. Optional: end-cap orientation bump; 1/2/3 pips for cell position in chain.

## 6.5 ⭐ v6.1 ADDENDUM — PHYSICAL FIT-TEST FINDINGS (2026-06-12)

Mridul printed the full PETG batch on an **Anycubic Kobra Neo (0.4mm nozzle)** and reported
real failures. These are MEASURED FACTS — design to them from now on:

### FDM limits learned on this printer (PETG, 0.4mm nozzle)
- **Raised features < 2.5mm wide = mush.** All 1.4–1.6mm braille dots distorted. PETG parts
  now use bold shapes only (≥3mm ridges/grooves); real braille ONLY on resin parts.
- **Horizontal round holes in vertical walls fuse closed** (magnet pockets did). All side-wall
  pockets now have **teardrop tops** (see `teardrop_magnet_pocket()` in outer_box/pod_params).
- **0.4mm sacrificial bridges don't adhere** (single layer) → all bridges now 0.6mm.
- Pilot holes print ~0.2–0.3 undersize → all pilots enlarged (M2: 2.0, M2.5: 2.3).
- Snap features <1mm tall don't function → lips/nibs ≥0.8–1.0mm now.

### Hardware spec corrections (measured on real parts)
- **Magnets are 8mm dia × 1mm thick** (CAD previously assumed 3×2!). Now **2 per docking
  face at y=±14** (center magnet removed — an 8.4mm pocket at y=0 would hit the pogo
  window). Polarity: cell −X = N/S, +X = S/N, pod +X = S/N.
- **ULN2003 module measured 20mm tall with vertical Duponts** vs 16mm pocket. FITS with
  wires soldered flat (~12mm). Mid-plate got a relief slot at the (+X,−Y) corner.
  Muscle-board PCB fab DEFERRED — prototype runs the module flat on the pocket floor.
- **DevKit + header strips fit the pod** ✓ (validated in hand).
- The v5 box bottom "orientation ridge" was placed INSIDE the wall (y=−32.5) — it never
  printed at all. Rebuilt as a 45° diamond ridge on the outer face.

### Manufacturing decision: LINKAGES ARE NOW RESIN-PRINTED
No laser-cut vendor available → linkage.scad rev 3.1 prints in tough/ABS-like resin,
8 pcs (6+2 spares), in `print_batch/Batch4_Resin/`. Fallback to laser-cut metal only if
resin proves too fragile. linkage.scad reference table refreshed for inner_radius=12.

### Docs
`docs/SOURCING.md` created (springs + pen-spring fallback, 2mm balls, pogo deferred,
fasteners). `docs/WIRING_AND_ASSEMBLY.md` updated: ULN2003 solder-flat procedure,
comb-less linkage install (step 10 still referenced the comb deleted in v6.0 — fixed),
2× 8×1mm glue-in magnets per face.

### v6.1b — pod shell DISCONNECTED-GEOMETRY bugs (found via Nef volume count)
The pod shell STL contained NINE bodies (CGAL `Volumes: 10` incl. outside):
1. **Switch "snap nibs" floated 5mm off the wall** and there was NO back support —
   pressing a nav button would shove the switch into the pod. Replaced with real
   `switch_cages()`: side fins + solid back wall rising from the floor (press force
   path wall→switch→back wall→floor), corner shelf tabs, switch drops in from top,
   legs VERTICAL (side-legs would foul the fins), hot-glue dab to secure.
2. **Lid screw bosses floated 0.5mm off the inner wall** (x=25 vs wall at 28) —
   printed as loose/spaghetti towers. `lid_screw_x` 25→27.5 (embeds 2mm into wall);
   lid holes follow the same param.
LESSON: check `Volumes:` in the render output, not just `Simple:` — Simple stays
"yes" for disconnected junk. Target = 2 (outside + one connected solid).

3. **Barrel jack hole overflowed the lid edge** (center x=−30, Ø11.5, lid edge ±32)
   → printed as an open NOTCH (confirmed in fit-test photo). A panel-mount jack
   can't clamp in a notch. Moved to (−22, 18) — fully inside the lid, offset in Y
   off the DevKit footprint (board y±14); guard ring is now a full circle.
   Photo evidence also confirmed: the old y=0 CENTER magnet pocket merged into the
   pogo window (only 2 of 3 pockets visible on the print) — vindicates the v6.1
   2-magnets-at-±14 layout. Lid recess face printed as exposed infill → workshop
   slicer needs ≥5 top/bottom solid layers (print settings, not CAD).

4. **base_plate underside ribs DELETED** (confirmed via fit-test photo): (a) printing
   flat put the ribs on the bed and BRIDGED the plate body over 3mm of air → waffle
   underside; (b) the ribs crossed the box corner-boss seats (±26,±21) so the plate
   sat 3mm too high — would have pushed the whole cam/standoff/top-plate stack up and
   the top plate ~2mm above the box rim. Solid 5mm plate is stiff enough.

### Homing-magnet spec gap (OPEN — cam side)
`braille_cam.scad` expects a **3×2mm** homing magnet (3.2 pocket, flush). Mridul's
in-hand magnets are 8×1mm. Decision: **buy 3×2mm discs** (added to SOURCING.md) rather
than carve an 8.2mm pocket into the 2mm cam base (would leave 0.8mm floor + widen the
hall window ~27°). Hall sensor stays at base_plate y=20 (validated on breadboard).
